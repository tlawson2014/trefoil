# Trefoil (TFL)

A Cosmos SDK chain where every account can nominate guardians, and losing
your key is no longer the end. Three interlocking rings — none can be pulled
free without the others.

Design doc: [docs/DESIGN.md](docs/DESIGN.md) — the pitch, the coin, the recovery rules, roadmap and open questions.

## What's in here

Almost everything in this folder is standard Cosmos SDK plumbing generated by
Ignite. The Trefoil-specific parts are:

| Path | What it is |
| --- | --- |
| `proto/trefoil/recovery/v1/` | The data shapes: a guardian set, a recovery request, the two parameters, and the four transactions. Everything else is generated from these. |
| `x/recovery/keeper/msg_server_*.go` | The four transactions: **set-guardians**, **request-recovery**, **approve-recovery**, **cancel-recovery**. Each file's top comment explains its rules. |
| `x/recovery/keeper/abci.go` | The end-of-block job that executes recoveries whose waiting period is over, and drops expired requests. |
| `x/recovery/keeper/helpers.go` | Small shared helpers (block time, guardian lookup, expiry). |
| `x/recovery/keeper/recovery_test.go` | Tests for the whole flow — the design doc's "definition of done" as code. |
| `x/recovery/types/errors.go` | Every reason a recovery transaction can be rejected, with a stable error code. |
| `x/recovery/types/params.go` | The two dials: recovery delay and request expiry. |
| `config.yml` | The local test network: accounts, the validator, zero fees, shortened timings. |

## How recovery works (prototype v1)

1. **Set guardians.** An account picks 1–7 guardians and a threshold that is a
   strict majority (for 3 guardians: 2 or 3). Guardians can never spend.
2. **Lose the key.** The owner makes a brand-new wallet.
3. **Request.** A guardian submits `request-recovery <lost account> <new address>`.
   This counts as the first approval.
4. **Approve.** Other guardians approve until the threshold is met. At that
   moment the waiting period starts (48h on a real network; 60s locally).
5. **Cancel window.** During the wait, the lost account's *original* key — if it
   still exists — can `cancel-recovery`. That's the defence against a stolen
   key or tricked guardians.
6. **Execute.** When the wait ends, the chain moves the account's entire balance
   to the new address and carries the guardian set across. No human signs
   this step; it happens at the end of a block.

Requests that never reach the threshold expire (7 days real / 1h local).

**v1 limitation:** the balance moves to a *new address*. Coins that are
staked stay on the old address. Keeping the *same* address (rotating the key
underneath it) is the v2 design and needs wallet support to be usable.

## Run it

Everything below happens in the Ubuntu (WSL) window.

### 1. Run the tests

```bash
cd ~/trefoil
go test ./x/recovery/... -v
```

You want every line to say `PASS` and, at the bottom, `ok  trefoil/x/recovery/keeper`.

### 2. Start the chain

```bash
cd ~/trefoil
ignite chain serve
```

The first run compiles everything (several minutes). When you see lines with
`height=` ticking up, Trefoil is producing blocks. Leave this window open.

### 3. The recovery walkthrough

Open a **second** Ubuntu window (Start → Ubuntu). Then:

```bash
# Shorthand so the commands stay readable.
alias t='trefoild --keyring-backend test'

# Who's who
t keys list
TOM=$(t keys show tom -a)
G1=$(t keys show guardian1 -a)
G2=$(t keys show guardian2 -a)
G3=$(t keys show guardian3 -a)

# Tom's balance before anything happens (5,000 TFL = 5000000000utfl)
t q bank balances $TOM

# 1. Tom sets three guardians, any 2 must agree
t tx recovery set-guardians $G1,$G2,$G3 2 --from tom -y
sleep 6
t q recovery get-guardianset $TOM

# 2. Rehearse the veto first: start a recovery, then Tom cancels it
t keys add newtom
NEWTOM=$(t keys show newtom -a)
t tx recovery request-recovery $TOM $NEWTOM --from guardian1 -y
sleep 6
t tx recovery approve-recovery $TOM --from guardian2 -y
sleep 6
t q recovery get-recovery $TOM          # executeat is set: the 60s clock is running
t tx recovery cancel-recovery $TOM --from tom -y
sleep 6
t q recovery get-recovery $TOM          # "not found": cancelled
t q bank balances $TOM                  # still 5000000000utfl

# 3. Now lose the key for real
t keys delete tom -y
# Tom can no longer sign anything. Try it:
t tx bank send tom $NEWTOM 1utfl -y     # fails: key not found

# 4. Guardians recover him
t tx recovery request-recovery $TOM $NEWTOM --from guardian1 -y
sleep 6
t tx recovery approve-recovery $TOM --from guardian2 -y
sleep 6
t q recovery get-recovery $TOM          # executeat = now + 60

# 5. Wait out the delay, then check
sleep 70
t q bank balances $NEWTOM               # 5000000000utfl — the coins moved
t q bank balances $TOM                  # empty
t q recovery get-guardianset $NEWTOM    # guardians followed Tom to his new address
t q recovery get-recovery $TOM          # not found: closed

# 6. Prove one guardian is not enough
t tx recovery set-guardians $G1,$G2,$G3 2 --from newtom -y   # (already set, but harmless)
t tx recovery request-recovery $NEWTOM $G3 --from guardian1 -y
sleep 70
t q bank balances $NEWTOM               # unchanged: one approval never executes
```

### 4. Stop

`Ctrl+C` in the first window. To wipe the chain and start fresh:
`ignite chain serve --reset-once`.
